The assignment 1 structure I built is organized around keeping input, code, and output separate. Raw data goes in data/raw/ and is never modified, which avoids skewing results and ensures it can be reused as a true source. Processed data goes in data/clean/ and is reproducible so it's safe to touch. Code lives in scripts/, kept apart from the data and output files, and written with relative paths so the project can run anywhere it is cloned. I used output/ instead of results/ because to me output is whatever a script or program emits, while results are the specific graphs and figures selected for a report. I feel like output is the broader category and results are a selection from it. Run and error information goes in logs/, and docs/ and README.md hold the notes that explain where files came from, what they contain, and how everything is run. Generally I put a project overview in README.md and more specific testing/creation/data documentation in docs. I did not include a config/ directory in this example since I have not used one before. I expect that to change as projects get more complex if the same settings need to be shared across several scripts.
Documentation is what makes computational work accountable. It is what lets me compare results across runs, understand what output actually is, and avoid misunderstanding how data was processed. Documentation can be the way errors which are otherwise silent are caught. I think this course will help me make errors in my work less silent, filling in knowledge gaps and understanding more of underlying processes.
